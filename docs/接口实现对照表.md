## 实现边界

交付物是 `kmp/`。112 个端点的验收位置是 `kmp/shared/network/`；`src/api/mock/` 和 `android-shell/` 是 Web 规格参考，不计入 KMP 验收。Ktor 3.6.0（CIO engine）+ `EndpointCatalog` 112 条 + `{code,message,data,trace_id}` 统一信封 + `SyncEngine`（`sync_queue` 指数退避重试）；写操作本地优先入队。`MeowApp` 在启动时构造 `KtorMeowApi` 并注入 `SyncEngine`，`AppGraph.api` / `AppGraph.sync` 供全 App 使用。后端 host **只来自用户填的 `sync_base_url` 等设置键**；未配置时默认禁用远程同步，绝不把账单/设备号/令牌发到样本原 App 的生产域名（见下方「网络与隐私门禁」）。所有网络失败由 `SyncEngine.flush` 的退避重试吞掉，绝不阻塞已经落库的 UI 写操作。下表记录 KMP 状态。`docs/功能差距表.md` 逐组登记 112 个路径。设计见 `docs/superpowers/specs/2026-11-11-kmp-full-replica-design.md` §3.4。

## 契约层约定

- 请求：明文 JSON；字段名与 `spec/endpoints.json` 一致。自建后端不复现样本 so 的 `data=<native 加密串>` 私有加密，按 `04` §5 的明文 JSON 契约实现（功能等价）。
- 请求体形状：`@Field` 端点把 `fields` 逐字段放进一个顶层 JSON object；`@Body` 端点把 `body` 整个作为请求体，不额外包一层、不与 `fields` 合并（样本端点不混用二者，同时给会抛 `IllegalArgumentException`）。GET 端点把 `fields` 作为 URL query 参数，**不发送请求体**。
- 通用请求头：`HeaderProvider`（`kmp/shared/network/ApiHeaders.kt`）在每次请求时注入 `Authorization`（已登录为 `Bearer <token>`，未登录省略该头）、`X-Device-Id`（Android 用 SharedPreferences 持久化 UUID）、`X-App-Version`（packageInfo / BuildConfig.VERSION_NAME）、`X-Client-Time`（**Unix epoch 毫秒，十进制字符串**）。`Authorization` **只取真实服务端令牌** `user_setting.auth_token`（`serverToken()`）；本机账号的 `AccountRepository.refreshLogin` 生成 `local_...` 假串，绝不冒充服务端令牌，也不再回退 SharedPreferences。`KtorMeowApi` 的 `headerProvider` 可替换，便于测试注入。
- 响应：`{ code: 0, message: "", data: {...}, trace_id: "..." }`；`KtorMeowApi.call` 调 `Envelope.unwrap`，`code != 0` 抛带 `path`、`code`、`trace_id` 的 `ApiException`；非 2xx HTTP 状态抛异常；信封解析失败抛 `IllegalArgumentException`。这些异常由 `SyncEngine.flush` 捕获并按退避重试。
- 配置域：`Config/GetV2` 由 `PlatformContracts.configGetV2` 显式传 `urlType = "configManage"`，走配置域；其余走主域（见下方「网络与隐私门禁」）。
- 列表包装：`{"items": [...]}`，兼容 `items` / `bills` / `list` / `data` / 裸数组。
- 时间：`yyyy-MM-dd HH:mm:ss`；`day` 为 `yyyyMMdd` 整数；预算 `day` 为 `yyyyMM`。
- 金额：整数分；写入前校验字符串金额，禁止浮点累加。
- 幂等：`bill` 复合主键 `(member_id, client_id)`；`client_id` 为端侧幂等键。
- 超时（对齐 `d0/a.java`）：connect 30s / call 120s / read 60s / write 60s / ping 5s。
- 字段来源：`@Field` 与 `@Body` 的 key 按 `spec/endpoints.json` 注册；`MemberTag/Create` 保留源码大写 `BillBookId`，并兼容小写。
- 动态 URL：下载用 `prepareRequest(...).execute` + `ByteReadChannel` 8 KiB 分块**真流式**读（不整体缓冲进内存，100 KiB 文件产生多个 chunk）；OSS 直传用 `submitFormWithBinaryData` 发 multipart。两者在 `DynamicEndpoints` 各登记一条 `@Url` 能力，并作为 `SyncEngine.enqueue` 的合法 path。**两者都不注入 app 通用头**（`Authorization` / `X-Device-Id` / `X-App-Version` / `X-Client-Time`）：预签名 OSS/CDN 地址是第三方 host，多余头会破坏签名校验；调用方需要携带的签名头通过可选 `headers: Map<String,String>` 参数显式传入。
- 入队守卫：`SyncEngine.enqueue` 用 `EndpointRegistry.isKnown(path)` 校验，path 必须是 112 条注解路径或 2 个动态 `@Url` id 之一；清单外路径（含旧代码里的 `Bills/BatchUpdate`）一律拒绝。批量改分类逐笔入队真实的 `Bills/Update`，`BillsRepository.batchUpdate` 与 `saveWithBalance` 共用同一个 `billItemPayload` builder，发**完整 `Items<BillItem>`**（`memberId` / `clientId` / `money` / `billType` / `day` / `desc` / `memberCateId` / `billBookId`），不再只带 `memberCateId`；账单 create/delete 分别入队 `Bills/Create` / `Bills/Delete`，均由 `BillsRepository` 落库后触发。
- 送达：`SyncScheduler`（进程级 `CoroutineScope` + `Dispatchers.Default`）在每次入队后不等待地触发 `flush()`；App 启动时 `flushOnStart()` 补发遗留条目。网络失败在 `flush` 内吞掉并退避重试。`SyncEngine.flush` 用 `kotlinx.coroutines.sync.Mutex.withLock` 串行化，并发触发不会把同一条队列项发两遍。
- 陈旧队列项：老版本可能直接写入过已下线路径（如 `Bills/BatchUpdate`）。`flush()` 对 `EndpointRegistry.isKnown` 为 false 的行**不发送、不重试**，直接标成终态 `status = 2`（`markSyncDropped`，`error = "path not in catalog: ..."`），避免永远卡在队列里。

## 网络与隐私门禁

- **默认不发往样本原域名**：`HttpConfig.MAIN_BASE` / `CONFIG_BASE` 是 `com.android.miaoa.achai` 原 App 的第三方生产域名，只保留作契约自检 / mock 测试的默认 host（`SpecBaseUrlProvider`）。生产装配用 `SettingsBaseUrlProvider`（`kmp/shared/network/BackendConfig.kt`），base 只来自用户配置。
- 设置键（都在 `user_setting` 表，经 `SettingsStore` 读写）：`sync_base_url`（自建后端主域）与 `sync_config_base_url`（可选配置域，空白回退主域）在设置页有编辑入口（`SettingsHome`，`kmp/ui/src/commonMain/kotlin/com/meow/ledger/ui/manage/AccountPages.kt`），保存前经 `validateSyncUrl`（`kmp/shared/src/commonMain/kotlin/com/meow/ledger/shared/network/BackendConfig.kt`）校验：空白合法（禁用远程同步），非空白必须为 `http://` / `https://` 且带主机名，并拒绝样本原生产域名；`auth_token`（真实服务端令牌）无新增 UI。
- `sync_base_url` 为空白时**远程同步禁用**：`SyncEngine` 的 `remoteEnabled = { remoteSyncEnabled(db) }` 让 `flush()` 一条都不发、条目保持 `pending`；`KtorMeowApi` 的 `baseUrlProvider` 也返回 `null`，即便被直接调用也抛异常而不发请求。账单、设备号与令牌都不会离开本机。填好地址后，之前入队的条目会在下次 `flush()` 补发。
- 配置好时：主域请求发到 `sync_base_url`；`Config/GetV2`（`urlType = "configManage"`）发到 `sync_config_base_url`，该键空白则复用主域。base 与相对 path 由 `HttpConfig.compose` 拼接，容忍尾斜杠有无。
- 验证：`:shared:jvmTest` 覆盖「空白 base → 0 请求且条目保持 pending」「配置 base → 请求落到该 host」「配置域回退主域」「auth_token 之外无令牌来源」。

- KMP 契约清单应读取 `spec/endpoints.json`，按 112 条注解路径逐条注册；同名重载按请求体区分。

- KMP 验证命令：`:shared:jvmTest`、`:app:assembleDebug`；Android 能力在真机或仪器测试验证。
