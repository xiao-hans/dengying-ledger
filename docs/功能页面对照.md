## 全局刷新机制

`src/app/useRefresh.ts` 提供 `RefreshCtx`（`version` + `bump()`）；`App` 在最外层持有版本号，
`useAsync()` 把 `version` 加入依赖。任何写操作（新建/编辑/删除账单）调用 `bump()` 后，
所有已挂载页面与随后返回的页面自动重新拉取数据，不需要用户手动刷新，也不会出现旧数据残留。

## 灯影风格一致性

- 颜色、玻璃面、圆角、字阶全部来自 `src/theme/tokens.ts` 的 CSS 变量；新页面没有硬编码颜色。
- 选中态继续使用「更亮更实的玻璃面 + 半粗文字」（`.chip.selected`、`.pick-tile.selected`），不是墨色实底。
- 顶部品牌头、胶囊搜索/筛选、玻璃卡、底部 Dock、空态按钮、二次确认对话框、底部 Sheet 全部复用共享组件。
- 每个二级页都有明确返回入口；每个空态都有下一步动作；危险操作都要求二次确认。

## 自动记账链路（M5）

```
粘贴通知 / 页面 / OCR 文本
  → parseRaw() 提取金额（整数分）、商户、收支方向
  → matchRule() 最长关键词命中 → 分类 / 账户 / 标签
  → dedupKey = digest(sourceApp + money + floor(occurredAt/60000) + merchant)
  → auto_raw（原始事件） + auto_event（待确认队列，idx_hash unique）
  → BillIdentified 逐条修改 / 批量通过 / 忽略
  → confirmEvent() → Bills/Create 写 bill → status=1
  → Bills/AutoBillsCallBack 回传识别统计
```

Web 无系统级通知监听、无障碍节点树、MediaProjection 与 OcrLite native so，三路均以「你主动粘贴文本」等价输入；权限用途逐项说明、引导可全程跳过，不申请任何系统权限。识别结果一律先入队，确认前不写 bill。

## Web 版剩余缺口

以下条目在 Web 规格参考里确实没有接入（逐项核对 `src/app/routes.tsx` 与 `src/features/account/` 后修正）：

- **老用户数据迁移**：没有独立页面；`ChangePhone`（换绑手机）、`ContractInfo`（合约信息）、`AppLock`（应用锁）、`Feedback`（意见反馈表单）、`PermissionExplain`（权限逐项说明）、`PushSetting`（推送 no-op 页）、`RemoteSwitches`（24 项远程开关编辑）**都已在 `src/app/routes.tsx` 注册并有实现**，不属于缺口。
- **支付宝解签**：`Order/AlipayUnSign` 端点在 `spec/endpoints.json`，Web 规格参考未登记对应页面。
- 合约信息的展示页已注册（`ContractInfo`），但「老用户数据迁移」入口只以卡片形式附在账号页，不是独立页面。
